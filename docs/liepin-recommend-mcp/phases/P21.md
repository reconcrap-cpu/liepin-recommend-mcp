## Learnings
- 推荐页 `立即沟通` 不是直接跳转 `/chat/im`。
- 首次沟通真实行为是发送默认打招呼语，然后可能出现两种反馈：
  - 轻量 popover：`已向候选人发送消息...`
  - 推荐相似候选人 modal：`已向{候选人}发送打招呼语...`
- 反馈出现后，详情 modal 内按钮会从 `立即沟通` 变成 `继续沟通`。
- 点击 `继续沟通` 后会在推荐页内打开基础聊天 modal，而不是新开 chat page。
- 基础聊天 modal 中可验证：
  - `.im-ui-basic-chat-header-name`
  - `.im-ui-basic-chat-header-basic-info-content`
  - `.im-ui-basic-chat-header-jump-btn`
  - `.im-ui-action-button.action-item.action-resume`
- P21 的正确聊天入口定义为：`recommend_basic_chat_modal` 中候选人姓名匹配，且 action bar 有 `索要简历`。
- 早期失败探针也触发了真实打招呼语发送；这是 P21 真实动作测试的副作用，需要在未来真实动作测试前继续明确授权。
- 推荐详情 close button 有时 `button.click()` 可关闭，有时不稳定；P21 close helper 已加入 reload fallback，确保不会把页面卡在详情 modal。

## Pitfalls
- 不要只等 `/chat/im` target；推荐页沟通动作可以只打开同页基础聊天 modal。
- 不要把基础聊天 modal 的空壳当成功；必须等 header/message/action bar 文本填充。
- 不要只识别 `im-ui-recommend-chat-modal`；轻量 welcome popover 也是成功发送后的有效中间状态。
- `button.click()` 会真实发送打招呼语；即使后续验证失败，也可能已经产生副作用。
- 推荐列表会因为已沟通候选人变化而刷新，`startIndex` 对应的具体人选会变化；验证必须记录候选人姓名与 resume id。
