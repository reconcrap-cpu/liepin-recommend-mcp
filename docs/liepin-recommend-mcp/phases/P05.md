# P05

## Goal
从推荐页稳定打开详细简历 modal，并抓取 `printable-content` DOM 快照，至少完成 5 份 live 验证。

## Actual Changes
- 实现 recommend sampler：
  - tab 切换：`推荐` / `最新`
  - 打开首位候选人
  - modal 内 `下一位`
  - modal 关闭
- 对 recommend modal 快照做标准化：
  - `sectionTitles`
  - `normalizedSectionIds`
  - `normalizedActionTokens`
  - `textHash`
  - `structureSignature`
  - `captureSource`
- 新增 `research acquisition-probe`，把 recommend DOM 与对应 network 请求一起落成可复跑证据。
- 追加反爬保护：
  - discovery 会识别 `safe.liepin.com` / `captchaPage` 为 `risk` target。
  - recommend sampler 只在当前 recommend target 可用时继续；若当前页自身跳到风控页会立即中止。
  - recommend 翻页默认增加 `3500ms` 冷却，避免快速连续打开详情。

## Live Validation Evidence
- `node src/cli.js research recommend-sample --limit 20` 成功抓取 20 份 recommend modal 详情，确认 `printable-content` 可稳定读取。
- `node src/cli.js research acquisition-probe --debug-port 9222` 的 recommend 部分验证了：
  - DOM 可直接读到 `job_match / job_intent / work_experience / education / languages / attachment_resume`
  - 打开详情时出现稳定 network 请求：
    - `com.liepin.recruitbff.lpt.recommend.get-recommend-resumes`
    - `com.liepin.rresume.usere.pc.get-resume-detail`
    - `com.liepin.rresume.usere.comment.list-bpc`
    - `com.liepin.rresume.operatorrecord.get-resume-recruit-record`
- 实际 modal selector 已登记在 `research/selector-ledger.md`。

## Learnings
- recommend modal 的“可供 screening 的正文”已经在 DOM 内，不需要先依赖图片/OCR。
- `get-resume-detail` 等 network 请求存在，后续可作为 coverage audit 或 drift 诊断的辅助手段，但 v1 文本解析不必先依赖它才能起步。
- `captureSource` 必须区分 `recommend_tab_推荐` 与 `recommend_tab_最新`，否则 survey 无法看出样本是从哪个池子来的。

## Pitfalls
- recommend 列表是漂移的，同一命令两次运行拿到的候选人集合并不固定。
- 重复抓取 recommend 详情会触发风控验证码，当前实测会把 recommend tab 重定向到 `safe.liepin.com`，这会阻断继续采样。
- 验证码通过后，Chrome 里可能仍残留旧的 `safe.liepin.com` tab；只要当前 recommend target 正常，不能把这个旧 tab 当成当前流程仍被阻断。

## Next Phase Notes

- 后续 survey 不能假设一次 recommend/最新各扫一轮就一定满足 50 份，需要做多轮补样和停止条件控制。
- 后续任何批量 recommend 采样都必须先跑 `research discover`，确认 `riskBlocked=false`，并保持低频分批。
