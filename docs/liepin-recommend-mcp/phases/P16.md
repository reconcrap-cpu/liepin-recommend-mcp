## Learnings
- 当前 chat `有简历` 列表中，20 个候选人里只有 7 个仍是 `索要简历`，其余大多是 `看简历` 或 `索要中`。
- P16 证明 P14 的 skip policy 能直接保护 LLM 调用量：非 `索要简历` 候选人不会进入 LLM。
- `screening-config.json` 当前仍缺失；P16 live 验收使用显式 `--mock-llm` 跑完整 structured screening 控制流。
- Mock LLM 只用于阶段安全验收；真实 provider 配置存在时，CLI 会走 P12 OpenAI-compatible JSON 路径。

## Pitfalls
- Dry-run 即使 LLM 返回 `request_resume`，也不能调用 P15 action executor。
- 不能把 `wouldPostAction` 当作已经执行的动作；真实动作必须等后续非 dry-run 阶段明确接线。
- 缺少真实 LLM 配置时不能静默 fallback；必须显式 `--mock-llm`，否则应报可修复配置错误。
- Candidate limit 以 candidate rows 计数，system row 只作为 observed/skipped row，不计入 20 个候选人目标。
