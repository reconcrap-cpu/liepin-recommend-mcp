# P06

## Goal
从聊天页 `看简历` 路径进入 `resume/detail` 并抓取详细简历快照；阶段门槛是至少验证 5 份 live 样本。

## Status
`PASSED`

## Actual Changes
- 实现 chat sampler：
  - 左侧会话行读取
  - `看简历` 点击后等待新的 `resume/detail` target
  - 读取 detail 页 `printable-content`
- 新增聊天分段过滤切换，当前支持通过精确文本点击 `有简历`。
- 将聊天状态标准化为：
  - `索要简历`
  - `索要中`
  - `看简历`
  - `浏览简历`
  - `UNKNOWN`
- 新增 `research acquisition-probe` 的 chat 部分，自动汇总当前会话状态分布并抓取一份可打开的 `resume/detail` 样本。
- 修复 chat sampler：
  - 系统行标记为 `rowType=system`
  - 候选人行优先使用 `data-tlg-ext.to_imid` 作为稳定 `rowKey`
  - 跳过系统行，避免把 `收到简历` 聚合入口当普通候选人
  - 对采样结果按 `textHash` 去重
  - 支持新打开 target、已有 `resume/detail` target URL 变化、以及已有 detail target 复用
  - `看简历` / `浏览简历` 动作支持按钮 selector 与文本 fallback

## Learnings
- chat 页确实存在“先看按钮文本再决定是否 screening”的状态分流基础，这与用户要求一致。
- `有简历` 过滤后的列表会出现系统行 `收到简历 已为您筛选出投递人选`，而且当前 DOM 下可能重复出现，需要单独建 taxonomy。
- chat `resume/detail` DOM 与 recommend modal 有交集，但不完全相同；当前看到的是 `extra_info` 更常见、`attachment_resume` 未出现。

## Pitfalls
- 当前账号 chat 页只有 3 位可用候选人，所以原始“至少 5 份”门槛在当前页面无法达到；用户已确认该缺口是样本池现实限制，不视为 blocker。
- `node src/cli.js research chat-sample --limit 5 --filter 有简历` 已从 `0` 修复为 `3`，并覆盖当前全部可用候选人。
