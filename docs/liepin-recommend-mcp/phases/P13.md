## Verified DOM Sources
- `conversation_row`:
  - 左侧会话行文本。
  - 提供稳定 `rowKey`，来自 `data-tlg-ext.to_imid`。
- `chat_header`:
  - 右侧候选人顶部摘要完整文本。
- `header_basic_info`:
  - 姓名、活跃状态、求职状态、地点、年龄、学历、毕业/工作年限。
- `header_user_info`:
  - 求职状态、地点、年龄、学历、毕业/工作年限。
- `header_resume_summary`:
  - 最近经历/学校专业、沟通职位、求职期望。
- `header_ext_info` / `header_ext_content`:
  - 与 header resume summary 重叠，但作为 DOM 冗余来源保留。
- `message_list`:
  - 当前沟通消息和未读/已读提示。
- `action_bar`:
  - `索要手机`、`索要微信`、`索要简历`、`约面试` 等动作按钮。

## Learnings
- 对 `索要简历` 候选人，chat 页右侧 header 已提供足够的筛选输入：
  - 基础信息
  - 当前/最近经历
  - 学校专业
  - 沟通职位
  - 求职期望
  - 沟通消息
- `索要简历` 状态下右侧 header 可能显示 `查看简历` 文本，但底部 action 仍有 `索要简历` 按钮；按用户规则，此状态仍代表尚未获得完整简历。
- 当前 P13 只读 DOM，不点击 `索要简历`，因此没有副作用。

## Pitfalls
- `有简历` filter 下仍会混入 `索要简历`、`索要中` 和系统 row，不能把 filter 名称理解成“都有完整简历”。
- 同一候选人可能在 DOM 中重复出现，必须用 `data-tlg-ext.to_imid` 去重。
- `浏览简历` 系统 row 必须继续跳过，不能混入普通候选人。
- `header_ext_info` 和 `header_ext_content` 与 `header_resume_summary` 有重复，后续 LLM payload 可以保留原始来源，也可以在 P14/P16 前做去重策略，但不要丢失未验证信息。
