## Decision Matrix
| Surface / State | CV Access In v1 | Acquisition Method | Screening Implication |
| --- | --- | --- | --- |
| recommend modal | yes | DOM `printable-content` primary; network detail endpoint recorded as evidence | recommend screening can parse full modal CV |
| chat `resume/detail` from `看简历` | yes | DOM `printable-content` primary; network detail endpoint recorded as evidence | chat screening still skips because CV is already available/requested |
| chat `索要简历` | no detailed CV yet | chat row DOM/action labels only | only this state can enter chat screening later |
| chat `索要中` | no new CV to fetch | state classification only | skip without LLM |
| chat `看简历` | detailed CV already available | can open `resume/detail`, but no screening needed in chat flow | skip without LLM |
| chat `浏览简历` / system row | possible detail route, but not normal candidate row | skip as system unless a later phase explicitly creates taxonomy-only handling | skip without LLM |
| attachment / portfolio gated area | metadata visible, full gated content not guaranteed | record presence/action labels; no auto preview/download in v1 | parser must include metadata but not assume attachment text |

## Learnings
- DOM coverage is sufficient for v1 across recommend modal and chat `resume/detail`; network routes confirm the same underlying resume detail APIs but are not required for first parser implementation.
- `attachment_resume` appears in both recommend and chat detail DOM as visible metadata/action area.
- Chat state discovery and CV acquisition are separate:
  - `索要简历` is screenable later but has no full CV.
  - `看简历` has full CV but must skip screening in chat mode by user rule.
- The acquisition probe must reselect the intended chat row before clicking, because scanning rows mutates the active conversation.

## Pitfalls
- The chat list can contain duplicate-looking rows and system rows; acquisition code must prefer stable row keys and candidate rows.
- `浏览简历` may appear on system aggregation rows; do not treat it as a normal candidate conversation.
- Network endpoints include risk/bright-risk calls; seeing those endpoints is normal evidence, but navigation to `safe.liepin.com` is still a hard stop.
