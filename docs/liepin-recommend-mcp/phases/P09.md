## Learnings
- P07 snapshot 的 `sectionTitles` 会包含公司/项目等 item header；parser 不能只依赖 DOM header list。
- 当前 parser 以 `fullText` 中的已知 section heading 为主进行切分，更适合后续 LLM payload 覆盖审计。
- `recruit_records` 和 `resume_notes` 经常在简历底部出现，即使不属于核心 CV section，也应该进入 schema，避免 LLM payload 丢尾部内容。
- `attachment_resume` 在 schema 中作为文本/metadata section 保存，不表示附件正文已被下载或 OCR。

## Pitfalls
- Parser 现在只做 section-level 归档，不尝试把工作经历逐条结构化成公司/职位/时间；这是刻意保守，避免在 DOM 结构尚未进入 P10 验证前过拟合。
- `job_match` 是 recommend modal 独有；chat detail 缺失该 section 是正常情况。
- `presentSectionIds` 来自 parser 对全文的切分，可能比 P07 taxonomy 的 `normalizedSectionIds` 多出 `recruit_records`、`resume_notes`，这是预期的覆盖提升。
