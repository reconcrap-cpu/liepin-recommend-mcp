## Learnings
- 推荐 tab active class 仍是 `.ant-lpt-segmented-item-selected`，但切换后短时间可能出现卡片已更新、selected class 尚未稳定的窗口。
- P19 tab 切换验证不能只看 active class；还需要接受“点击后卡片列表确实变化且有候选人”的证据。
- 详情 modal 关闭后可能有动画残影或 `#preview` hash 残留。
- 关闭验证应等待 modal/printable 不存在或不可见，而不是只等 modal root 立即消失。
- 关闭成功后需要清理 `#preview`，避免后续流程误以为仍处于预览态。
- `下一位` 按钮 selector `.button-turn-next` 可稳定推进到不同候选人；10 次连续推进均得到唯一 snapshot。
- P19 继续只做读/遍历，不点击 `立即沟通` 或 `超级聊聊`。

## Pitfalls
- 不要把 `activeLabel=""` 直接视为 tab 切换失败；要结合 card list change。
- 不要在 close 后立即断言 modal root 不存在；Ant/页面动画会导致短暂误判。
- 当前推荐页可能已经加载了大量卡片；P19 遍历器会先 `scrollTo(0, 0)` 再打开起始卡片。
- P19 不重新证明 infinite scroll 底部；P19 依赖 P18 修正后的 terminal-signal 审计结论。后续若要跨已加载列表末尾继续遍历，必须复用 P18 的保守底部判定。
