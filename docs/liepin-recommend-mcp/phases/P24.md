## Goal
把 P23 异步 run 面补成更适合生产操作的形态：默认状态输出不再携带庞大 workflow payload；每个完成 run 持久化 screen input、LLM request、decision、coverage 工件；任何真实 `chat` 或 `request_resume` 副作用都必须有显式审批参数。

## Actual Changes
- 更新 `src/run-state.js`：
  - `markRunCompleted` 会为新完成的 workflow run 写入拆分工件：
    - `screen-input.json`
    - `llm-request.json`
    - `decision.json`
    - `coverage.json`
  - 新增 `artifact_summary`，记录工件路径、`itemCount` 和 workflow。
  - 新增 `summarizeRun` / `buildRunStatusPayload`，默认 status/list 输出只保留 operator 需要的摘要、路径和错误信息，不嵌入完整 `result`。
- 更新 `src/worker.js`：
  - `recommend_chat_chain` 执行前必须有 `allow_chat_action=true`。
  - `execute_request_resume=true` 执行前必须有 `allow_request_resume=true`。
  - 缺少审批时 run 失败为 `SIDE_EFFECT_APPROVAL_REQUIRED`，executor 不会被调用。
- 更新 `src/cli.js`：
  - `recommend-chat start` 需要 `--allow-chat-action`；如果启用 `--execute-request-resume`，还需要 `--allow-request-resume`。
  - `research recommend-chat-chain` 同样需要 `--allow-chat-action`。
  - `research recommend-action --action chat` 需要 `--allow-chat-action`。
  - `research chat-action --action request_resume` 需要 `--allow-request-resume`。
  - `runs list` / `runs status` 默认输出 compact payload；传 `--full` 可查看完整 run。
  - 新建 run 的 `phase` 更新为 `P24`。
- 更新 `src/json-rpc.js`：
  - MCP start tools schema 增加 `allow_chat_action` / `allow_request_resume`。
  - MCP start tools 在创建 run 前执行同样的副作用审批校验。
  - MCP `liepin_run_status` 默认返回 compact run payload。
- 更新测试：
  - `src/run-state.test.js`
  - `src/worker.test.js`
  - `src/json-rpc.test.js`

## Learnings
- Old P23 runs are not backfilled with `artifact_summary`; the new split artifacts are guaranteed for runs completed after P24.
- Compact status is much easier to read during operation, but still exposes artifact paths so the full evidence can be inspected deliberately.
- The worker-level approval gate is the important final guard: even if a caller bypasses CLI/MCP preflight and writes a run directly, side-effect workflows fail before browser action.

## Pitfalls
- Do not run `recommend-chat start` or `research recommend-chat-chain` without an explicit operator decision; `--allow-chat-action` is now required because it clicks real `立即沟通` / `继续沟通` paths.
- Do not combine `--execute-request-resume` with real pages unless `--allow-request-resume` is also present and the operator has approved the resume request side effect.
- Use `runs status --full` only when debugging detailed payloads; the default compact status is the normal operator view.
