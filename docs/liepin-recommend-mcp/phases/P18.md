## Learnings
- 推荐筛选入口在无筛选时显示 `筛选`，有筛选时显示类似 `筛选·6`，后续必须用 prefix `筛选` 而不是 exact match。
- P18 实机证明筛选生效可通过应用前后卡片数量变化验证：本次从 20 变为 11。
- `重置 + 确定` 能恢复干净状态；恢复前需要读取 drawer 内 `selected=[]` 来确认没有残留。
- 推荐页 infinite scroll 远不止 40 张卡；修正后实机到底为 969 张卡。
- 推荐页到底不能只看第一次 `atBottom=true`；需要持续触底滚动、等待延迟加载、做 up/down probe，并确认终止提示。
- 猎聘推荐页终止提示不是通用的 `到底` / `没有更多`，本次实机是 `我也是有底线的`。
- Chat 页列表滚动容器可以从 `.im-ui-contact-list-item.im-ui-contact-item` 的祖先节点中发现。
- Infinite scroll 审计应使用 `textContent` 生成短签名；`innerText` 会触发昂贵 layout，曾导致 chat 页 CDP evaluate 超时。
- CDP client 的 per-call timeout timer 必须在 resolve/reject 后清理，否则 Node 进程会看起来多卡 30 秒。
- `try/finally` 中返回异步审计结果必须 `return await`；直接 `return promise` 会让 `finally` 提前断开 CDP socket。

## Pitfalls
- 旧的 `safe.liepin.com` target 可能残留在 Chrome target list 中，但用户实际前台页可以是 chat 或 recommend；判断是否阻断必须看是否存在正常 recommend target 与 `riskBlocked`。
- P18 第一次失败后留下了 active filters；修复后 executor 起手会先打开 `筛选·N` 并 reset，恢复了干净状态。
- Recommend scroll audit 后页面可能停在列表底部；后续打开筛选抽屉前不能假设页面位置。
- `recommend-scroll-audit-20260421-194816.json` 是 false positive，不得作为后续 P19/P20 infinite scroll 依据。
- 筛选项标题会反映选中值，例如 `薪资范围（单选）5K-8K`、`年龄20岁-30岁`；匹配 filter group 仍需 prefix 容错。
