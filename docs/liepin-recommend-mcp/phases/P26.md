## Learnings
- Chat 页前几行常常全是 `看简历` 或系统行，所以 `llmCalls=0` 不等于 real provider 不工作；需要把采样窗口推进到真正出现 `索要简历` 的位置。
- 拆分 artifacts 不能只按 recommend workflow 的字段形状建模；chat workflow 需要显式保留 `rowIndex`、`beforeState` 和 `chatInputManifest`。
- 在当前桌面沙箱里，即使本地配置正确，provider readiness check 也可能因为网络限制报 `fetch failed`；这类命令要按权限规则提权重跑。

## Pitfalls
- P26 只验证真实 chat-page dry-run；没有执行任何真实 `request_resume`。
- 不要因为第一次 real run `llmCalls=0` 就把问题误判成 provider 异常，先看当前批次是否真的包含 `索要简历`。
- 不要在文档、终端回显或日志里泄露 `screening-config.json` 的 apiKey。
