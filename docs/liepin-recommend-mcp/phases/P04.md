# P04

## Goal
验证 Chrome `9222` 连接、猎聘页面发现和基础失效提示，让后续阶段可以稳定依赖 live page discovery。

## Actual Changes
- 新增基于原生 CDP websocket 的页面连接层，替代运行期对 Puppeteer 的依赖。
- 实现 `doctor`、`research discover`、MCP `liepin_doctor` 共用的页面发现逻辑。
- 将页面分类固定为 `recommend`、`chat`、`resume_detail` 三类。
- 扩展 CDP client，支持事件监听，为后续 network 研究和 selector drift 诊断打基础。

## Live Validation Evidence
- `node src/cli.js doctor --json` 在 2026-04-21 的实机结果中成功发现：
  - Recommend: `https://lpt.liepin.com/recommend#preview`
  - Chat: `https://lpt.liepin.com/chat/im#preview`
  - Resume detail: `https://lpt.liepin.com/resume/detail?...`
- `node src/cli.js research discover --debug-port 9222` 返回与 doctor 一致的 live target 分类。
- 未配置 `screening-config.json` 时会明确报出修复路径：`C:\Users\yaolin\.liepin-recommend-mcp\screening-config.json`。

## Tests
- `npm test`
- `node src/cli.js doctor --json`
- `node src/cli.js research discover --debug-port 9222`

## Learnings
- 对猎聘现阶段的研究工作，直接使用 page-level CDP websocket 比 Puppeteer 更稳定，也更容易拿到 network event。
- `doctor` 需要同时覆盖“配置缺失”和“浏览器/登录页存在”，否则新 instance 很难快速判断是环境问题还是 selector 问题。

## Pitfalls
- 大量 recommend 详情抓取后，推荐页可能被风控重定向到 `https://safe.liepin.com/page/liepin/captchaPage_PC?...`，这会让 `discover` 暂时找不到 recommend page。
- 因此后续阶段不能把“discover 失败”一律当作 selector drift，还要区分 captcha/risk page。

- 后续 `doctor/self-heal` 需要加入 captcha page 识别，而不是只判断“recommend 缺失”。
