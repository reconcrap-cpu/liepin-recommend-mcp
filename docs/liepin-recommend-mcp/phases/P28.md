## Learnings
- 对 operator 来说，长链路不是只有最终 `completed/failed` 才有价值；中途的 `stage + progress + lastItem` 才是真正能排障和盯盘的信号。
- same-target 回跳在 live 浏览器里会有瞬时 target 抖动；只用老 client 硬顶不够稳，重新拿 target 建连会更可靠。
- CLI 和 MCP parity 不能只看“都能启动 run”，还要验证它们中途读到的是同一套 progress 结构。

## Pitfalls
- P28 的 progress 目前主要覆盖 `recommend_chat_chain`；其他 workflow 仍然可能只有 completed/failed 终态信息。
- 历史 P27 及更早 run 不会自动补出 progress 字段；只有 P28 之后的新 run 会带这套运行中快照。
- 本阶段的 live evidence 含真实 `立即沟通` 和真实 `索要简历` 副作用，复验时仍需显式保留授权参数。
